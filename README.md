# VTB Cyberpolka 2026

## Что это?

Хакатон от ВТБ (Data Fusion Contest 2026). Задача — предсказать 41 финансовый продукт для 1 миллиона банковских клиентов. Данные анонимизированы, метрика — Macro ROC-AUC.

## Результат

**Топ 4%** в финальном leaderboard, не доделав полностью хакатон.

## Как это работало?

### 1. Главный инсайт — время

Клиенты идут по порядку ID: 1M-1.75M — это train, 1.75M-2M — это test. То есть данные имеют временную структуру. Обычный random K-fold давал утечку из будущего в прошлое. Сделал сплит по времени — качество выросло сразу на +0.05 по Macro AUC.

### 2. Classifier Chains

Вместо одной большой модели — 41 маленькая, каждая предсказывает свой продукт. Предсказания предыдущих моделей добавляются как признаки для следующих. Это ловит корреляции между продуктами (например, если у клиента есть кредитка, вероятно есть и зарплатный проект).

### 3. SVD на дополнительных признаках

Было 2241 дополнительных числовых признака. Сжать их в 100 главных компонент через SVD — и информация сохранилась, а шума стало меньше.

### 4. Флаги пропущенных значений

Пропуски в данных — это часто не шум, а сигнал. Создал бинарные признаки для топ-50 фичей с наибольшим количеством NaN. Например, пропуск в поле «сумма кредита» может означать, что кредита вообще нет — полезная информация.

### 5. CatBoost на GPU

41 модель, каждая обучается параллельно на GPU. Использовал auto_class_weights="Balanced" потому что данные сильно несбалансированы — некоторые продукты есть у 0.1% клиентов.

```
    ├── pipeline/                # Пайплайн обучения
    │   ├── phase1_svd.py       # SVD на доп. признаках
    │   ├── phase2_adversarial.py  # Проверка стабильности фичей
    │   ├── phase3_features.py # Фичевая инженерия

    └── ...
```

## Что не успел доделать

- 5 проблемных таргетов с AUC < 0.75 (самый сложный — 0.679)
- Optuna tuning для всех 41 модели
- Ансамблинг с LightGBM

Но даже такого результата хватило для топ-4%.
